# v0.4 — Registre et interaction avec les contrats

## Dépendance

v0.3 validée.

## À réaliser

- Importer et versionner une ABI, associer adresse/réseau/bytecode observé et préciser le niveau de vérification.
- Formulaires typés pour fonctions view/pure, écritures, tuples et tableaux dans le périmètre de test annoncé.
- Lire à une hauteur choisie seulement si le profil de stockage supporte l'état demandé ; expliquer les erreurs d'historique.
- Prévisualiser, simuler, estimer le gas puis faire signer par un portefeuille externe EIP-1193 de référence.
- Passerelle de transactions avec méthodes ETH explicitement autorisées, endpoints fixes, contrôle d'accès et quotas ; aucun accès QBFT/PERM/ADMIN depuis ce chemin.
- Vérifier chainId et genesis ; gérer refus utilisateur, mauvais compte/réseau, nonce concurrent, transaction en attente et revert.
- Suivre reçu, logs et état du contrat témoin dans l'interface.
- Déployer un artefact précompilé de référence depuis le portefeuille ; la compilation Solidity web est exclue.

## Critères de sortie

1. Importer le contrat témoin et lire son état.
2. Modifier son état via une transaction réellement signée par le portefeuille.
3. Voir le reçu, l'événement et la nouvelle valeur.
4. Un appel interdit par le contrat reste interdit même si le profil applicatif autorise le parcours.
5. Mauvais réseau et ABI invalide sont rejetés ; revert expliqué.
6. Aucune clé privée de compte n'apparaît dans API, PostgreSQL, logs ou fixtures publiques.
7. L'intégration du portefeuille utilise les méthodes qu'il supporte effectivement.

## Prompt

Implémente uniquement v0.4. Le parcours doit être utilisable avec un portefeuille de référence et la chaîne Besu réelle, sans gestion serveur des clés de compte.
